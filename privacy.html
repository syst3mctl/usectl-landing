01 Information We Collect

We collect and process the following categories of data to provide, secure, and operate the managed hosting platform:

  • Account & Authentication Data: Email addresses, password hashes, OAuth account links (e.g., GitHub, Google), and session credentials. Upon authentication, we issue stateless 24-hour JWT access tokens and database-backed 90-day refresh tokens. Refresh tokens are stored strictly as SHA-256 hashes.
  • Scoped Agent API Keys: When you generate long-lived API keys (usectl_agt_*) for automation or AI agents, only an 8-character prefix and a SHA-256 hash of the key are stored in our databases. The full key is displayed once upon creation and cannot be retrieved by platform administrators.
  • Application Telemetry & Container Logs: We collect container execution logs (via Loki), performance metrics (via Mimir), and request traces (via Tempo) to render application dashboards and trigger alert mechanisms. All tenant telemetry is strictly isolated through a namespace-locked observability gateway.
  • AI Model Invocation Data: If you utilize our AI Addons or Copilot capabilities, prompt metadata and token consumption counts are metered per project to enforce budget caps.

02 Encryption & Security Architecture

usectl implements rigorous technical and organizational controls to protect customer data:

  • Envelope Encryption at Rest: Secrets and environment variables are encrypted using self-hosted AES-256-GCM envelope encryption with fresh random nonces drawn on every cryptographic operation.
  • Protected & Masked Variables: Secret values marked as "protected" return "value": null across all API endpoints and are permanently prohibited from being revealed via the web UI or REST API. Non-secret variables are masked in viewer roles.
  • Tamper-Evident Audit Logging: All secret operations generate hash-chained audit log records where appends are serialized via database locks. Audit logs record metadata, key names, and actors—never raw secret values.
  • Universal Tenant Network Isolation: Every tenant machine namespace (kdeploy-<name>) is protected by automated NetworkPolicies enforced at the kernel/routing layer. Lateral cross-tenant network traffic between isolated namespaces is strictly blocked.
  • Container Runtime Sandboxing: High-risk workloads, browser instances, and sandboxed AI agents execute under gVisor (runsc runtime class) to ensure strict kernel-level container isolation.

03 Data Storage, Backups & Retention

  • Managed Services: Managed Postgres databases are backed up centrally via daily logical dumps.
  • Dedicated Database Services: Dedicated PostgreSQL instances run scheduled dumps streaming to tenant-scoped object storage buckets. Retention periods are set to 7 days for hourly backups and 30 days for daily backups.
  • Un-Snapshotted Stateful Addons: Redis, MongoDB, NATS, and unmanaged S3 bucket contents do not have automated volume snapshots enabled by default. Tenants are responsible for managing application-level data retention for these stateful services.
  • Container Images: The internal Harbor registry enforces a retention policy keeping the 5 most recent image tags per repository, with automated garbage collection to reclaim storage.

04 Third-Party Data Processors & Edge Routing

  • Edge Infrastructure: Web traffic to customer applications and admin interfaces routes through Cloudflare for Edge TLS termination and DDoS mitigation. Container image pushes bypass Cloudflare and connect directly to private registry nodes.
  • Transactional Email: Account lifecycle, billing alerts, and system notifications are dispatched via Google Workspace SMTP relays.
  • Payment Processing: Payment details, billing management, and invoices are handled by Stripe.
