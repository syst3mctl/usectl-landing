What you getOne namespace · one bill

A machine is a computer that is only yours.

A machine has its own resources, its own addons, its own domains, its own team and one bill. Underneath, it is Kubernetes — run by us, invisible to you. You see a box with a slider.

Isolated by defaultBare-metal speed behind ironclad kernel and network walls — no leaky multi-tenant hosts.
  • Hardened network perimeter — every machine sealed in its own namespace, ingress and egress policy enforced. Neighbours cannot sniff your traffic or reach your pods.
  • Kernel sandboxing — heavy workloads and AI agents run inside gVisor sandboxes, fully isolated from the host kernel.
  • Envelope-vault secrets — keys and env vars under AES-256-GCM envelope encryption with tamper-evident audit logs. Protected secrets never return plaintext.
Everything insideKill five SaaS subscriptions — the whole production stack lives in one machine.
  • Auto-healing data — two-instance PostgreSQL clusters with streaming failover, three-node NATS JetStream RAFT.
  • Storage, cron and edge TLS — Redis, MongoDB, S3 object storage, CronJobs and custom domains with automated TLS. No external addons.
  • Full-stack telemetry — Grafana dashboards for metrics, logs and traces, plus Sentry-compatible error tracking, all in one CLI.
One billOne budget, unlimited apps — no multi-app tax.
  • Unified resource wallet — a machine is a fixed budget of vCPU, RAM and storage on one predictable subscription.
  • Apps without bills — extra web services, workers or databases share the machine's budget. No new fees.
  • Stage and prod groups — sibling groups with isolated networks, each with its own database and namespace, on the same budget.
Workloads and previewsZero-downtime rollouts and an instant preview for every pull request.
  • Targeted pods — run workloads as web, worker or release, each owning its repo, branch, domain and ports.
  • Zero-downtime rollouts — rolling or recreate strategies with 5xx watchers and instant auto-rollback.
  • PR preview URLs — every pull request spins up an isolated preview with its own namespace and URL.

Apps inside a machine can be web, worker or release. Each has its own repo, branch, port, replicas and rollout. PR previews get their own namespace and URL.

FAQPlain answers

Questions people ask

Is a machine a VM?
No. It is a Kubernetes namespace with a network policy, a quota and its own secrets on nodes we operate. Container isolation, not a microVM. We say that plainly because it matters for some workloads.
Can I leave?
Yes. Your Dockerfile, your Postgres dump and your bucket run anywhere. If we disappeared tomorrow your stack still works.
Where is my data?
On bare metal we own at Hetzner in Falkenstein, Germany. With self hosted usectl, on your own hardware.
What about backups?
Managed Postgres is dumped nightly at the platform level. Dedicated Postgres gets scheduled backups to a private bucket only that database can reach.
Is there a bandwidth meter or a seat fee?
No and no. The sticker is the ceiling. The honest fine print: a single request tops out at 100 MB, and machines cannot talk to each other.
Do I need Docker?
Not for Next.js, Vite, Node or static sites. For anything else, a Dockerfile.
Who is behind this?
systemctl, a team in Tbilisi, Georgia. We own and run our servers at Hetzner ourselves.
What happens to my data if you shut down?
Your Dockerfile, your Postgres dump and your bucket already run anywhere. Backups are yours to download any time — from the Postgres panel, or straight over the S3 API.
