1 · Machine

$ usectl machines create my-app --vcpu 2 --ram 4 --storage 10
✓ namespace created

A machine is a namespace and a quota. It holds no code.

2 · Pod

$ usectl machines pods create my-app web \
    --repo github.com/you/your-saas --port 3000
✓ build complete (28s)

A pod is one workload. Three repos means three blades.

3 · Addons

$ usectl machines addons add my-app --type database
$ usectl machines addons add my-app --type cache
$ usectl machines addons add my-app --type worker
$ usectl machines pods attach-addon my-app web database cache worker

Provisioned is not attached. Three addons mean three attach calls.

4 · Domain

$ usectl machines pods set my-app web domain=my-app
✓ live at https://my-app.usectl.com

No domain, no route. Everything else is reachable only from inside.

what you getone namespace, one bill

a machine is a computer that is only yours.

on usectl a machine is a kubernetes namespace with a resource budget, its own addons, its own domains, its own team and one bill. you never see kubernetes. you see a box with a slider.

  1. 1

    isolated by default

    its own network policy, its own quota, its own secrets. a neighbour cannot reach you and you cannot reach it.

  2. 2

    everything inside

    postgres, redis, s3, cron, domains and tls live in the machine, not in five other dashboards.

  3. 3

    one bill

    a machine’s budget is shared by all its apps, addons and groups. adding a second app does not add a second bill.

  4. 4

    stage and prod

    split a machine into groups, each with its own namespace and its own database, on the same budget.

apps inside a machine can be web, worker or release. each has its own repo, branch, port, replicas and rollout. pr previews get their own namespace and url.

faqsix questions

questions people ask

is a machine a vm?
no. it is a kubernetes namespace with a network policy, a quota and its own secrets on nodes we operate. container isolation, not a microvm. we say that plainly because it matters for some workloads.
can i leave?
yes. your dockerfile, your postgres dump and your bucket run anywhere. if we disappeared tomorrow your stack still works.
where is my data?
on bare metal we own at hetzner in falkenstein, germany. with self hosted usectl, on your own hardware.
what about backups?
managed postgres is dumped nightly at the platform level. dedicated postgres gets scheduled backups to a private bucket only that database can reach.
is there a bandwidth meter or a seat fee?
no and no. the sticker is the ceiling.
do i need docker?
not for next.js, vite, node or static sites. for anything else, a dockerfile.
